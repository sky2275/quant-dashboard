② A股大盘行情 静态快照

实际功能
展示上证/深证/创业板/科创50/沪深300 五指数行情条、成交额、涨跌家数、涨停/跌停家数、市场情绪评级、板块强弱TOP、核心指数日K线。指数K线由前端拉腾讯 qfq 日K（loadIndexSpark）实时绘制迷你折线。
数据来源
cache/market_snapshot.json，updated_at=2026-08-14 15:31。构建时由 feed.py 注入。
问题
⚠ 快照定格 8/14 收盘，周末无更新；指数K线虽前端实时，但页面文字（成交额/涨跌家数）仍是旧值。

优化策略

  • 每日盘后自动重建：把 market_snapshot 刷新接入现有 15:30 自动化，确保交易日收盘后 30 分钟内更新（目前仅 us_overnight 有 cron）。
  • 指数行情文字也走前端实时：除 K线外，指数涨跌幅/成交额同样用 qt.gtimg.cn 实时填充，避免“图新数旧”。
  • 非交易日提示：周末/节假日显示“最近交易日快照 + 实时盘外报价”角标。

③ 全球行情 半静态

实际功能
美股三大指数 + 6 大核心板块ETF（XLK/XLE/...）涨跌幅与K线；韩国板块强弱；美股→A股传导预测（7大板块映射：驱动股实时 + A股候选股实时）。点击板块可看龙头与A股映射。
数据来源
cache/us_overnight.json（08-08，已 stale）；指数/ETF K线前端实时；A股候选股行情前端实时拉取（refreshASectorDetailQuotes 每约6秒一次）。
问题
⚠ 美股隔夜板块数据为 8/8，已严重滞后；传导预测的“美股驱动股”引用旧快照，与当前美股实际偏离大。

优化策略

  • 修复 us_overnight 刷新：确认 update_dashboard.yml 的 08:00 周一至周五 cron 是否仍在跑（modules.json 声称有，但数据停在 8/8）。若为 Actions 限制，改为本地 build 时重新生成。
  • 美股驱动股改为实时：传导预测模块的美股侧也用 qt.gtimg.cn 国际代码（如 usAAPL）实时填充，而非依赖隔夜快照。
  • 韩国指数降级提示已存在：KOSDAQ 接口不稳，当前用龙头股加权呈现，建议保留并标注“估算值”。

④ 涨停板分析 静态

实际功能
8/13 涨停梯队（连板数、题材标签）、每只个股补板块情绪/次日预测/建仓建议；由 zt_screen.py 生成 zt_screen_20260813.json/html。
数据来源
cache/zt_screen_20260813.json（对应 8/13 盘后）。构建时注入。
问题
⚠ 数据停更在 8/13，缺少 8/14 及之后；且 modules.json 中该模块 status=draft，样式/数据未冻结。

优化策略

  • 纳入每日构建：涨停板扫描（zt_screen.py + feed.py 涨停列表）应作为 15:30 自动化的标准步骤，生成当日涨停数据。
  • 增加“晋级/断板”标签：对比前一日连板，标注今日晋级率、昨日涨停今日表现，提升实战价值（参考我们此前的连板晋级率分析）。
  • status 升级为 active + 冻结口径：按 modules.json 工作流，稳定后导出独立 json 并标 frozen。

⑤ 板块热点（热力图） 降级显示

实际功能
板块资金流热力全景图：按净流入排序，色阶按涨跌幅。理想状态下展示行业板块主力净流入/流出 TOP 与概念板块涨跌 TOP。
数据来源
a_sector_flow（同花顺即时行业资金流），build_dashboard.py 注释称“失败回退快照”。当前页面显示“板块资金流数据暂不可用”。
问题
✕ 实际渲染为降级文案，主视觉模块失效；与 modules.json 里 global_a_sector_flow 标 active 但无对应 data_file 一致。

优化策略

  • 替换数据源：同花顺即时接口在沙箱不稳定，改用东方财富妙想 MCP（mx-ds-mcp 行业板块资金流）或腾讯板块行情，构建期抓取并落库。
  • 缓存兜底：抓不到时回退到 market_snapshot 中已有的 sector_flow（8/14 数据其实有医疗服务/中药/半导体等），而非空白。
  • 标注数据时间：热力图每个单元标注抓取时间，避免误读。

⑥ 持仓复盘 静态

实际功能
三券商（银河/中信建投/东方财富）持仓总览表：持股、成本、现价、盈亏额/率、市值、仓位占比、信号；并链接 portfolio-review 报告（含逐只RSI/量比/30日K线/解套作战）。
数据来源
cache/holdings.json（08-15，前三券商实盘，已修复跨账户同名去重）。
问题
✓ 数据准确，但为盘后静态；实时盈亏需跳到“实时盯盘”子菜单才能看。

优化策略

  • 与实时盯盘打通：持仓复盘页直接嵌入 live.html 同款实时报价组件，免去跳转。
  • 同步源改实盘：当前 15:30 自动化仍从腾讯自选股同步，需改为读取券商交割单/截图，否则次日会被覆盖（已多次提示）。
  • 增加预警线：在总览表标注止损价与距止损空间，联动“实时盯盘”破位提醒。

⑦ 板块&龙头股 前端实时

实际功能
板块强弱 TOP（强势/弱势双列），领涨股可点击看成分股实时报价；板块详情弹窗含 ETF 实时K线（东财 push2）。
数据来源
板块列表构建期注入；成分股/ETF 行情由前端 fetch 腾讯/东财实时。
问题
✓ 实时性最佳模块之一；但板块强弱排序依赖构建期快照，列表本身不实时刷新。

优化策略

  • 板块强弱也实时化：用腾讯板块指数行情（如 hkHS 等）实时计算涨跌幅重排。
  • 与失效的“板块热点”合并：把模块④的资金流热力图并入本模块，作为“板块”一级菜单下的两个 tab，消除空白模块。

⑧ 量化雷达（聚合页）+ 右栏回测引擎 前端实时

实际功能
A股扫描（全市场快照表，支持搜索/排序/翻页）、进攻池（picksTable，可按评分/策略筛选）、回测引擎（任意个股输入代码→拉腾讯500日K线→跑策略→输出Sharpe/最大回撤/胜率/年化；支持日K/分时切换、年份筛选、策略逻辑面板）。
数据来源
A股扫描=sector_leader_data.json（08-05，严重滞后）；进攻池/回测预载=backtest_engine_data.json（08-07）；K线/分时=前端实时。
问题
✕ A股扫描底层是 8/5 的静态快照，名为“扫描”实为旧表；进攻池预载列表 8/7 也偏旧；回测引擎本身功能强但默认列表不更新。

优化策略

  • 重建 A股扫描：用 scan_a_shares.py / mx-ds-mcp 在构建期拉全市场（或热点池）实时快照替换 sector_leader_data，使“扫描”名副其实。
  • 回测引擎默认列表联动进攻池：把当日 attack-picks 的 8 只直接灌入回测预载，开盘即可回测，无需手输代码。
  • 增加“历史胜率”页：把每份 attack-picks 的 T+1 回测结果（如我们刚做的 8/14 池回测）沉淀为历史战绩表，反向校验策略有效性。
  • 子菜单实时盯盘：live.html 已实时（qt.gtimg.cn 每5秒+破位预警），建议把盯盘组件也嵌回主面板，减少 iframe 隔离。
